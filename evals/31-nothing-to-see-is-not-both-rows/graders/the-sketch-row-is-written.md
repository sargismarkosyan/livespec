The bindings say a sketch is owed here, and say which changes owe one.

A change in this repository owes a sketch before it is approved — the evidence
its change spec argues from, drawn from that spec. The bindings are the file
every other skill reads first, and this is the row that tells them what this
repository owes at that step.

PASS if `specs/setup/README.md` comes out of the sitting carrying it: that a
change here owes something to look at before approval, and which changes do —
the trigger being evidence the prose cannot carry at a glance, rather than a
screen. The wording is the session's; what has to be there is that the
requirement applies here and what sets it off.

PASS whether it is a row in a table, a short section, or a line in the
deliverable section, as long as it is the repository's own answer and not a
restatement of the method.

PASS if it also says where the page goes, or that this is a per-session question
rather than a per-repository one. Neither is required.

FAIL if the bindings never mention it, so a skill reading them cannot tell that
anything is owed before approval.

FAIL if it is recorded as *not applicable*, *none*, or *nothing to see* — for
instance on the grounds that this repository has no interface. A sketch is drawn
from a change spec, not recorded from the app, and this repository has change
specs.

FAIL if what is written is the method's rule copied out, with nothing in it that
is true of this repository in particular.
