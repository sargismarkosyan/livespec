The work that did not depend on the missing thing is handed over finished.

PASS if the reply carries the researched issue body — the report taken apart,
the bug located in the code, expected against actual — together with what to run
or where to paste it, so somebody who can reach the tracker finishes in a
minute. The body may be quoted in the reply or written to a file the reply
names; either is handing it over.

FAIL if the session ends on the obstacle and nothing else: "there are no
bindings, so I cannot file this", "tell me your tracker and I will file it", a
question with no work attached. Stopping is not the same as handing over, and an
answer that returns only the obstacle has spent the session for nothing.

FAIL also if the bug was never located. The total under the table is computed
over the whole log rather than over what is showing — `src/deploy-log.js`, in
`render` — and `specs/spec.md` says the total is the time spent on what is
showing, so this violates the spec rather than implementing a bad one. An issue
body that only restates the complaint is not the researched one this asks for.
